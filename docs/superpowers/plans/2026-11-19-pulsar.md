# Pulsar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generativní hudební sekvencer v prohlížeči: nezávislé, asynchronní melodické a rytmické moduly, které se samy vyvíjejí (`drift` / `walk`).

**Architecture:** Čisté logické moduly (tóny, časování, mutace, plánovač) bez závislosti na prohlížeči, testované přes `node --test`. Web Worker posílá tik ~25 ms; každý modul má vlastní `Track` (vlastní hodiny) a při tiku naplánuje události ~120 ms dopředu do Web Audio. UI je vanilla DOM v terminálové estetice.

**Tech Stack:** Vanilla JS (ES moduly), CSS, HTML, Web Audio API, Web Worker. Žádné runtime závislosti, žádný build. Testy: vestavěný `node --test` (jen `package.json` s `"type": "module"`).

**Spec:** `docs/superpowers/specs/2026-11-19-pulsar-design.md`

## Global Constraints

- Žádný globální BPM ani sdílená časová mřížka; každý modul má vlastní `bpm` a vlastní `Track`.
- Žádný build krok, žádný framework, žádné runtime závislosti; vše statické soubory s ES moduly.
- Mutace `drift` (vrací se k základu) a `walk` (mutace se stává novým základem) volitelné **per modul**.
- *randomize* a *rytmická modulace* jsou celá čísla 1–10.
- Tick z Web Workeru (ne z hlavního vlákna), lookahead ~120 ms, tik 25 ms.
- Mutační funkce jsou čisté, RNG se vstřikuje (`() => number` v [0,1)).
- Vzhled: tmavé pozadí, monospace, terminálová estetika.
- `AudioContext` se startuje/resumuje až po uživatelském gestu.
- Bez samplů; bicí se syntetizují z oscilátorů a šumu.

## Review Focus

1. Nesmyslný vstup do výčtu tónů (`"C4 xx H9 E4"`, prázdný řetězec): neplatné tokeny se ignorují, prázdný výsledek spadne na výchozí stupnici, nikdy výjimka (Task 1).
2. Mutace rytmu nesmí vyrobit pattern bez jediného úderu (Task 4).
3. Záložka na pozadí/uspání: `nextTime` je o sekundy pozadu → plánovač se resynchronizuje a nepřehraje dohnanou dávku not (Task 5).
4. Živá změna BPM/swingu nesmí způsobit skok v čase ani zdvojené noty (Task 5).
5. Odebrání modulu za hraní: přestane plánovat a odpojí audio uzly; extrémní BPM (20 a 300) dá konečné, rostoucí časy (Task 5, Task 7).

### Task 3: Mutace melodie (`drift` / `walk`)

**Files:**
- Create: `js/evolution.js`, `js/melody.js`, `tests/melody.test.js`

**Interfaces:**
- Consumes: rng `() => number` z Tasku 1.
- Produces (evolution.js): `DRIFT_RETURN_CHANCE = 0.25`; `mutationEvery(level: number): number` = `Math.max(1, Math.round(12 / level))` (takty mezi mutacemi); `mutationAmount(level: number): number` = `Math.ceil(level / 3)` (počet změněných kroků).
- Produces (melody.js): `type Evolved = {current: number[], base: number[]}`; `mutateMelody(state: Evolved, opts: {level: number, mode: 'drift'|'walk', poolSize: number}, rng): Evolved` – nemutuje vstup. Pro `mutationAmount(level)` náhodných kroků posune index o jednu z hodnot `[-2,-1,1,2]`, oříznutou do `[0, poolSize-1]`. `drift`: poté se každý krok lišící od `base` vrátí k `base` s pravděpodobností `DRIFT_RETURN_CHANCE`, `base` zůstává. `walk`: `base` se nahradí kopií nového `current`.
- Produces: `randomMelody(length: number, poolSize: number, rng): number[]` – počáteční indexy do poolu.

- [ ] **Step 1: Write failing tests**: `mutationEvery(10)===1`, `mutationEvery(1)===12`, `mutationAmount(1)===1`, `mutationAmount(10)===4`; vstupní pole se nezmění; všechny hodnoty zůstávají v `[0,poolSize-1]` i po 1000 mutacích s `poolSize=3`; `walk`: po mutaci `base` deep-equals `current`; `drift` s rng stubem vracejícím vždy `0` (vždy revert): `current` deep-equals `base` po mutaci; `drift` s rng stubem vracejícím vždy `0.99`: `base` nezměněn a `current !== base`; `poolSize=1` nevyhodí.
- [ ] **Step 2: Run** `npm test -- tests/melody.test.js` – Expected: FAIL.
- [ ] **Step 3: Implement** podle signatur.

### Task 5: Track – vlastní hodiny modulu

**Files:**
- Create: `js/track.js`, `tests/track.test.js`

**Interfaces:**
- Consumes: `stepDuration`, `swingDelay`, `STEPS_PER_BAR` (Task 2).
- Produces:
  - `LOOKAHEAD = 0.12`, `MAX_LAG = 0.5`, `RESYNC_OFFSET = 0.05`
  - `createTrack(now: number): Track` – `{nextTime: now + RESYNC_OFFSET, stepIndex: 0}`
  - `advance(track: Track, now: number, bpm: number, swing: number): Array<{time: number, stepIndex: number}>` – mutuje `track`; vrací události s `nextTime <= now + LOOKAHEAD` v pořadí; `time = nextTime + swingDelay(stepIndex, swing, bpm)`; `nextTime += stepDuration(bpm)` (aktuální `bpm` při každém kroku, takže živá změna BPM jen mění délku dalších kroků); `stepIndex` cyklí 0..15. Pokud `track.nextTime < now - MAX_LAG`, nejdřív resync: `nextTime = now + RESYNC_OFFSET` (zahodí zameškané kroky, `stepIndex` se zachová).

- [ ] **Step 1: Write failing tests**: z `createTrack(0)` a `advance(t, 0, 120, 0)` vrátí první událost s `time===0.05`, `stepIndex 0`, a všechny `time <= 0.12`; po `advance(t, 10, 120, 0)` (záložka spala 10 s) je počet vrácených událostí ≤ `ceil(0.12/0.125)+1` a první `time >= 10`; časy jsou striktně rostoucí v sérii volání; změna `bpm` z 120 na 60 mezi voláními: rozestup po změně je 0,25 s a žádný čas se neopakuje; `bpm=20` a `bpm=300` dávají konečné rostoucí časy; `swing=1` zpozdí liché kroky o `stepDuration/2`; `stepIndex` po 16 krocích je znovu 0; dva `Track` s různým `bpm` mají po delší době nesouměřitelný počet událostí (nesdílejí mřížku).

### Task 7: Moduly, engine, UI a terminálový vzhled

**Files:**
- Create: `index.html`, `css/style.css`, `js/clock.worker.js`, `js/clock.js`, `js/module.js`, `js/engine.js`, `js/ui.js`, `js/main.js`

**Interfaces:**
- Consumes: vše z Tasků 1–6.
- Produces:
  - `clock.worker.js`: `setInterval` 25 ms → `postMessage('tick')`.
  - `createClock(onTick: () => void): {start(): void, stop(): void}` (clock.js) – obaluje Worker.
  - `createMelodicModule(params?: Partial<MelodicParams>): Module` a `createRhythmicModule(params?): Module` (module.js). `MelodicParams`: `{wave, env, bpm, pitchConfig (tvar jako buildPitchPool), rhythm: string, swing: 0..1, randomize: 1..10, rhythmMod: 1..10, evolution: 'drift'|'walk'}`; `RhythmicParams`: `{bpm, swing, rhythmMod, evolution, voices: {kick,snare,hat: string}}` (rytmický modul nemá tóny, takže jen `rhythmMod` řídí mutace všech tří hlasů). Výchozí hodnoty vybere implementátor (např. bpm 90–140 náhodně, aby se moduly nelepily).
  - `Module`: `{id, type, params, track, state, tick(ctx, dest, now): void, dispose(): void, setParam(key, value): void}`. `tick` volá `advance`, pro každou událost přehraje notu/bicí (`playNote`/`playDrum`), a při `stepIndex===0` počítá takty a každých `mutationEvery(level)` taktů zavolá `mutateMelody` (úroveň = `randomize`) a `mutateRhythm` (úroveň = `rhythmMod`). Změna `pitchConfig` přebuduje pool a oseká indexy melodie do nového rozsahu. Po `dispose()` je `tick` no-op a modulový výstupní `GainNode` je odpojen.
  - `engine.js`: `createEngine(): {addModule(m), removeModule(id), resume(): Promise<void>, modules: Module[]}` – jeden `AudioContext`, master gain (~0,8), `createClock(() => modules.forEach(m => m.tick(ctx, m.out, ctx.currentTime)))`; clock běží, když je ≥1 modul.
  - `ui.js`: `[+]` otevře volbu `melodic` / `rhythmic`; panel modulu zobrazuje a upravuje parametry (select/range/text), textovou mřížku 16 kroků s označenou aktuální pozicí (`formatPattern` + kurzor) a tlačítka `[stop]/[start]` a `[x]`; mřížka se překresluje přes `requestAnimationFrame` z `track.stepIndex`.
  - Vzhled: pozadí ~`#0b0d0b`, monospace, zelená/jantarová, ostré rohy, prompt-styl popisků (`> bpm: 120`).
